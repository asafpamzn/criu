Step 8: Threads

ret = dump_task_threads(parasite_ctl, item, defer_image_write);
// Iterates over item->nr_threads, skipping leader (already dumped)

Each thread is a separate scheduling entity with its own state. The leader's state is dumped in dump_task_core_all; additional threads are handled here.

Per-Thread State Captured

  • CPU Registers — general purpose, FP/SIMD via ptrace
  • TLS — Thread-Local Storage base address
  • Stack — signal alternate stack (sigaltstack)
  • Futex robust list — for pthread mutex cleanup
  • Scheduling — policy, priority, nice value
  • Seccomp filters — per-thread BPF filters
  • Private pending signals — per-thread signal queue
  • Cgroup — thread-level cgroup membership
  • LSM profile — AppArmor/SELinux context
  • rseq — restartable sequences state
  • clear_tid_addr — for CLONE_CHILD_CLEARTID
  • pdeath_sig — parent-death signal

How Threads Are Dumped

1
dump_task_rseq() — read rseq config via PTRACE_GET_RSEQ_CONFIGURATION (before infection)
2
parasite_dump_thread_seized() — parasite reads TLS, tid_addr, sas, comm, creds
3
dump_thread_core() — futex robust list, scheduler info, seccomp
4
fixup_thread_rseq() — if thread was in rseq critical section, redirect IP to abort handler
🔧 rseq fixup is critical: if a thread was mid-rseq when seized, its instruction pointer must be moved to the abort handler address, otherwise it would resume in an inconsistent state.
