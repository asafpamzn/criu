Step 1 Deep Dive: Zombies & Misc Fields

Zombie Processes

if (item->pid->state == TASK_DEAD)
    // zombies are dumped separately
    // in dump_zombies()
    return 0;

A zombie is a process that has exited but whose parent hasn't called wait() yet. It has:

  • No memory — all VMAs freed
  • No file descriptors — all closed
  • No threads — all terminated
  • No signals — handler table gone
  • Only task_state = TASK_DEAD and exit_code remain
// dump_one_zombie() — minimal core image
core->tc->task_state = TASK_DEAD;
core->tc->exit_code = pps->exit_code;
The exit_code encodes both the signal that killed it (bits 0-6) and the exit status (bits 8-15). CRIU preserves it exactly so the parent's wait() returns the correct value after restore.

Misc Fields

loginuid
Read from /proc/PID/loginuid. Part of the Linux audit subsystem. Records the original UID that logged in via SSH/PAM. Unlike real/effective UID, it survives su/sudo. If not restored correctly, you may lose ability to SSH into the container after migration.

⚠️ Dumping loginuid is marked as critical in the code.
oom_score_adj
Read from /proc/PID/oom_score_adj. Range: -1000 to +1000.
-1000 = never OOM-kill this process
+1000 = kill this first when OOM occurs
Databases and caches (like Valkey) often set this to -1000 to avoid data loss.
child_subreaper
Set via prctl(PR_SET_CHILD_SUBREAPER). When a child's parent dies, orphaned descendants re-parent to the nearest subreaper instead of PID 1. Used by systemd, container init processes, and process supervisors.
dumpable
Controls whether ptrace attach and core dumps are allowed. If 0: /proc/PID/maps is restricted (root only). Set via prctl(PR_SET_DUMPABLE). SUID binaries auto-clear it. CRIU needs it to be dumpable=1 during dump; restores the original value.
