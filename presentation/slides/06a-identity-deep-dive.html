Step 1 Deep Dive: Process Identity & Metadata

All read from /proc/PID/stat via parse_pid_stat() — the very first thing dump_one_task does.

Process Identity

pid
Process ID within its namespace. CRIU must restore the exact same PID so that /proc/self, kill(pid, ...), and any PID stored in shared memory still work.
sid — Session ID
Groups processes for terminal control. The session leader's PID == SID. Ctrl+C sends SIGINT to the entire session. CRIU must recreate session membership on restore.
pgid — Process Group ID
Used for job control: kill(-pgid, sig) signals the whole group. Foreground/background job switching depends on this. Shell pipelines share a pgid.
comm — Command Name
Up to 16 characters. Shown in ps, top, /proc/PID/comm. Set from argv[0] or prctl(PR_SET_NAME). Cosmetic but important for monitoring.
flags — Kernel PF_* Flags
Kernel-internal process flags: PF_FORKNOEXEC (forked, not exec'd), PF_SUPERPRIV (used root privs), PF_SIGNALED (killed by signal). Restored in core image.

Memory Layout Boundaries

Virtual addresses defining the process memory map:

start_code / end_code
.text segment — executable machine code. Read-only, shared across fork()s. Defines where the program's instructions live.
start_data / end_data
.data + .bss segments — initialized globals and zero-initialized globals. Writable, COW'd on fork().
start_stack
Main thread's stack bottom. Grows downward on x86/arm. Other threads' stacks are in separate mmap'd VMAs.
start_brk
Heap start (brk area). The current brk value (heap end) is read separately via the parasite's brk(0) call.
arg_start/end, env_start/end
argv[] and environ[] strings in memory. Defines what /proc/PID/cmdline and /proc/PID/environ show. Must be in the exact same location after restore.
