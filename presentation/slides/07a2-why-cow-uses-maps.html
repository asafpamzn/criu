Why COW Dump Can Use maps Instead of smaps

// collect_mappings() in cr-dump.c
use_maps = opts.cow_dump && opts.lazy_pages;
ret = use_maps ? parse_maps(pid, vma_area_list, dump_file)
               : parse_smaps(pid, vma_area_list, dump_file);

What Standard CRIU Needs from smaps

VmFlags line
2-letter codes for kernel VM flags:
gd = MAP_GROWSDOWN (stack)
lo = MAP_LOCKED
nr = MAP_NORESERVE
ht = MAP_HUGETLB
dp = MAP_DROPPABLE
io/pf = VM_IO/VM_PFNMAP (unsupported)
ss = shadow stack
sr, rr, dc, mg, hg, nh, wf = madvise flags
Memory accounting stats
RSS, PSS, Shared/Private Clean/Dirty — used by standard CRIU for page tracking decisions. The kernel must walk all PTEs to compute these.

Why COW Doesn't Need Them

No dirty-page accounting needed
COW mode uses userfaultfd write-protect (UFFD-WP) to track writes in real-time. Every first write triggers a WP fault → CRIU snapshots the page. No need for kernel's dirty-page stats.
VmFlags derived from filename
The critical flag is MAP_GROWSDOWN (stack). COW uses set_maps_derived_flags() to detect it from the [stack] filename in maps output — no VmFlags line needed.
All pages transferred anyway
COW dump sends all pages (bulk transfer), then converges on dirty pages. It doesn't need per-VMA RSS/PSS to decide what to transfer.
Performance impact: For a 100GB Valkey process, parsing smaps takes 2-5 seconds (page table walk). Parsing maps takes <1 millisecond. This saves precious frozen time.
