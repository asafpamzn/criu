Page Classification: Skipped, Holes, and Dirty

During pagemap scanning, every page falls into one of three categories. Two are often confused.

① Skipped (zero/unmapped)
Page is not present in RAM or swap, or is the kernel zero page. Silently skipped — never enters the page-pipe at all.
// should_dump_page():
if (!(pme & (PME_PRESENT | PME_SWAP)))
    skip;  // not in RAM, not in swap
if (__page_is_zero(pme))
    skip;  // kernel zero page
Restore naturally has zeros for these addresses. No action needed.
② Parent Hole (clean page)
Page exists in memory (present, non-zero) but is NOT soft-dirty since last clear_refs. Already in parent image → tell restore to get it from there.
// generate_iovs():
if (has_parent && page_in_parent(softdirty))
    page_pipe_add_hole(pp, vaddr,
                       PP_HOLE_PARENT);
// Only on 2nd+ pre-dump (has_parent=true)
Entered into page-pipe as a hole. Restore side fetches from parent image layer.
③ Dirty Page (must dump)
Page exists in memory AND has been modified (soft-dirty set). Must be captured into the current image.
// generate_iovs():
page_pipe_add_page(pp, vaddr, ppb_flags);
// ppb_flags may include PPB_LAZY
// for demand-paged restore
Page contents transferred to image. On first pre-dump ALL present pages are dirty (no baseline).

The Layered Image Model (incremental pre-dumps)

Pre-dump 1 (parent) — no baseline
ALL present pages dumped (has_parent=false)
Page A Page B zero Page D
↓ clear_refs → process runs → some pages modified
Pre-dump 2 (incremental) — has parent
Only dirty pages + parent holes
hole→A Page B' zero hole→D

Why parent holes matter

Without parent holes
Every incremental pre-dump becomes a full dump. The restore side wouldn't know which pages to get from parent vs current image. Parent holes are the mechanism that makes incremental pre-dump efficient.
Zero pages are different
Zero/unmapped pages are NOT in the page-pipe at all. They don't need to be in parent images either — the kernel naturally provides zeros for unmapped addresses. Don't confuse them with parent holes!
First pre-dump: no holes
has_parent=false, so page_in_parent() always returns false. All present pages are classified as dirty → all get dumped. Parent holes only appear starting from the 2nd pre-dump.
