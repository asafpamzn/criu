Pre-dump: Page Drain Modes

SPLICE Mode (default)

How it works
The parasite (running inside the target) calls vmsplice(SPLICE_F_GIFT) to move page frames into pipe buffers. This is a zero-copy PTE transfer — the kernel remaps the physical pages from the process into the pipe, no memcpy needed.
Tradeoff
Pro: Zero-copy — fastest possible read
Con: Happens during freeze — process is stopped while pages are drained through the parasite

READ Mode (pre_dump_mode=read)

How it works
drain_pages() is skipped entirely during freeze. Only iovecs (page addresses) are recorded. Actual page contents are read after unfreeze via process_vm_readv() from outside.
Tradeoff
Pro: Shorter freeze window — pages read after resume
Con: Pages may be modified between unfreeze and read — stale data for incremental tracking. Only safe for pre-dump (not final dump).

CLONE Mode: Neither!

Skip both drain and pagemap
CLONE mode doesn't drain pages during freeze at all. It registers VMAs for UFFD-WP tracking and reads pages after unfreeze via process_vm_readv() in the bulk transfer phase. Changes tracked by WP faults.
