CLONE Mode: Skip the Pagemap Scan Entirely

Standard Pre-dump (during freeze)

// generate_vma_iovs() — standard path:
pmc_get_map(pmc, vma);  // ★ read pagemap from kernel

// generate_iovs() — page-by-page loop:
for (vaddr = start; vaddr < end; vaddr += PAGE_SIZE) {
    should_dump_page(pmc, vma->e, vaddr, &info);
    if (has_parent && page_in_parent(info.softdirty))
        page_pipe_add_hole(pp, vaddr, PP_HOLE_PARENT);
    else
        page_pipe_add_page(pp, vaddr, ppb_flags);
}
// 200GB = 52 MILLION iterations while process is frozen
Cost: 2-5 seconds of freeze time just for the pagemap scan. Then more time for drain_pages(). Process completely unresponsive.

CLONE Mode Fast Path (during freeze)

// generate_iovs() — CLONE fast path:
if (opts.clone_dump && lazy_capable) {
    // No pagemap scan at all!
    // Just register the VMA for lazy transfer
    struct lazy_vma_entry *lve = xmalloc(sizeof(*lve));
    lve->vma = vma;
    lve->total_pages = vma_entry_len(vma->e) / PAGE_SIZE;
    lve->dst_id = vpid(item);
    lve->source_pid = item->pid->real;
    lve->sent_bitmap = xzalloc(bitmap_size);
    
    list_add_tail(&lve->list, &global_lazy_vmas);
    return 0;  // ← Done! No per-page work.
}
Cost: O(1) per VMA — just a malloc + list_add. No pagemap I/O, no per-page loop. Entire VMA registered in microseconds.

Key insight: Standard CRIU uses soft-dirty + pagemap (scan all pages during freeze). CLONE mode uses userfaultfd write-protect (track writes after unfreeze, zero scan during freeze). The dirty tracking moves from "freeze time" to "runtime" — the process tells us what it writes, we don't have to ask.
