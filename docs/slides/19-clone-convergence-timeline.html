CLONE WP_ASYNC: Convergence Timeline & Gaps

Current CLONE Convergence (Memory Only)

① Dump freeze (~51ms)
Capture ALL state: regs, FDs, signals, timers, memory pages, VMA layout
SIGCONT → source running again
② Bulk transfer (~58s)
8 TCP streams, process_vm_readv + LZ4. Source serving traffic.
③ Wait for idle threads
Poll /proc/PID/task/*/syscall — all in epoll/futex/nanosleep
④ SIGSTOP → PAGEMAP_SCAN → fork snapshot
Find dirty pages, fork for consistency, SIGCONT source (~1ms)
⑤ Read dirty pages from fork
Consistent snapshot across 8 streams. Kill fork.
⑥ Second SIGSTOP → final scan + new VMAs
Near-zero dirty. Detect new mmap extents → PS_IOV_VMA_DIFF
⑦ SIGCONT + close all streams
Migration complete.

What's Missing for General-Purpose

Between ① and ⑥, the source is alive. Anything it does to non-memory state is lost. This is analogous to how pre_dump only captures memory, and the full dump must re-capture everything.

Resource What can happen Needed at convergence
Threads pthread_create/exit Re-seize, ptrace new threads, dump regs/TLS
FDs open/close/accept/dup2 Re-drain FD table via parasite
Signals sigaction(), new pending Re-dump sigactions + PTRACE_PEEKSIGINFO
Timers timer_settime, new timers Re-read via parasite
FS context chdir/chroot/umask Re-read from /proc + parasite
Socket state New connections, queue data Re-dump socket repair + queues
The pre-dump → dump analogy:
pre_dump = memory-only snapshot (process stays alive)
dump = full snapshot of everything

Current CLONE convergence = memory-only re-sync (like pre_dump)
Missing: a "convergence dump" that re-captures non-memory state
(= essentially a second dump_one_task at step ⑥)
Why Valkey doesn't need it: Single event loop, fixed thread count, stable FD set (listen + client sockets only change via accept() which is reflected in memory state), no sigaction() changes, no timer creation. The memory-only convergence is sufficient for this specific workload.
