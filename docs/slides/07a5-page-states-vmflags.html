smaps Page States & VmFlags

Page States

Referenced
Pages accessed (read or written) recently. The kernel tracks this for its LRU page reclaim — unreferenced pages get swapped out first. Not directly used by CRIU — informational only.
Anonymous
Pages with NO file backing — they exist only in RAM (and swap). Created by: heap (brk/mmap(MAP_ANONYMOUS)), stack, CLONE'd pages after fork(). All anonymous pages must be dumped by CRIU — there's no file to re-read them from.
LazyFree
Pages marked with madvise(MADV_FREE). The process says "I don't need this data anymore, but don't bother freeing the page right now — reclaim it when you need memory." The kernel can drop these without swapping. Used by memory allocators (jemalloc) to return pages cheaply.

VmFlags — 2-Letter Codes

The VmFlags: line encodes kernel vm_flags. CRIU parses these in parse_vma_vmflags().

mmap() Flags (restored via mmap arguments):

gdMAP_GROWSDOWNStack — grows downward on access
loMAP_LOCKEDmlock'd — cannot be swapped out
nrMAP_NORESERVENo swap reservation (overcommit)
htMAP_HUGETLBHuge pages (2MB x86 / 512KB arm)
dpMAP_DROPPABLEKernel can discard under pressure

madvise() Flags (restored via madvise calls):

srMADV_SEQUENTIALSequential access — aggressive readahead
rrMADV_RANDOMRandom access — disable readahead
dcMADV_DONTFORKDon't copy to child on fork()
ddMADV_DONTDUMPExclude from core dumps
mgMADV_MERGEABLEEnable KSM (dedup identical pages)
hgMADV_HUGEPAGEUse Transparent Huge Pages (THP)
nhMADV_NOHUGEPAGEDon't use THP (sparse access)
wfMADV_WIPEONFORKZero content in child after fork

Special Kernel Flags:

ioVM_IOI/O mapped (device MMIO) — can't vmsplice
pfVM_PFNMAPRaw PFN mapped — can't vmsplice
ssShadow StackIntel CET / ARM BTI security
