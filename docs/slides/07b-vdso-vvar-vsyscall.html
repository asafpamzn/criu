Special Kernel VMAs: vDSO, vvar, vsyscall

The kernel injects these mappings into every process. They're not created by the process itself.

vDSO — Virtual Dynamic Shared Object

A tiny shared library (~4KB) mapped by the kernel into every process's address space at a random address (ASLR).

Contains optimized syscalls:

  • gettimeofday()
  • clock_gettime()
  • getcpu()

These run entirely in userspace — no kernel trap needed. Reads time data from vvar pages directly.

Architecture-specific: different code on x86_64 vs aarch64. CRIU must parasite_fixup_vdso() because the address may differ on the destination machine.

vvar — Virtual Variable Pages

Read-only data pages mapped alongside vDSO. Contains the kernel's live timekeeping data:

  • Current wall-clock time
  • Monotonic clock parameters
  • Clock multiplier & shift values
  • Sequence counter for lock-free reads

The vDSO code reads these pages directly — no syscall needed to get the time.

Mapped with special kernel flags: VM_IO | VM_PFNMAP | VM_DONTEXPAND | VM_DONTDUMP. CRIU has a special exemption for vvar in its io_pf unsupported-VMA check.

vsyscall — Legacy (x86_64 only)

Predecessor to vDSO. Fixed address:

0xffffffffff600000

Same syscalls as vDSO but at hardcoded addresses — a security risk (no ASLR).

Modern kernels emulate it: the page is mapped but accesses trap to the kernel, which then executes the real syscall. Much slower than vDSO.

Being phased out. Not present on aarch64.

CRIU marks it as VMA_AREA_VSYSCALL.

// handle_vma() in proc_parse.c — detection by name
if (!strcmp(file_path, "[vsyscall]"))    vma->status |= VMA_AREA_VSYSCALL;
else if (!strcmp(file_path, "[vdso]"))   handle_vdso_vma(vma);   // VMA_AREA_VDSO
else if (!strcmp(file_path, "[vvar]"))   handle_vvar_vma(vma);   // VMA_AREA_VVAR
