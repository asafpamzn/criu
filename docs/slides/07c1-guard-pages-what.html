MADV_GUARD_INSTALL — What Are Guard Pages?

A guard page is an unmapped hole in the address space that triggers SIGSEGV on any access. Created with:

madvise(addr, len, MADV_GUARD_INSTALL);

Primary use case: stack overflow protection.

When a thread's stack grows, it approaches a guard page. If the stack overflows, it hits the guard → SIGSEGV → clean crash instead of silently corrupting adjacent memory.

The Invisibility Problem
Unlike regular VMAs, guard pages are NOT represented as struct vm_area_struct in the kernel. They're invisible in:
  • /proc/PID/maps — not listed
  • /proc/PID/smaps — not listed
  • Kernel VMA linked list — not present
They exist only as PTE-level markers (unmapped entries with a special poison value).
