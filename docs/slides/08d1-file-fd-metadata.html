Regular Files: What CRIU Saves

CRIU saves the file descriptor metadata, NOT the file contents.

Per Regular File FD

Saved in the image
File path — /var/log/app.log
File offset — e.g. 50KB (where the cursor is)
Open flags — O_WRONLY | O_APPEND | O_CREAT
File mode — permissions (0644)
File locks — flock/fcntl if any
NOT saved
File contents, directory entries, filesystem state. CRIU never reads or copies the actual data inside the file. That's your responsibility.

What CRIU Does on Restore

// Simplified restore logic:
fd = open("/var/log/app.log",
          saved_flags);   // O_WRONLY|O_APPEND
lseek(fd, saved_offset);  // seek to 50KB
// → process resumes writing
The file must exist on the destination
CRIU opens the file by the same path. If the file doesn't exist, restore fails. Options:

• Shared filesystem (NFS/EFS) — same file on both machines
• Copy files before restore
• Application creates it — process opens with O_CREAT
Valkey case: Data lives in 100GB of anonymous memory (dumped by CRIU). RDB/AOF are persistence files managed by Valkey itself — not part of the CRIU FD restore path.
