smaps Memory Accounting: The Two Axes

Per-VMA stats computed by walking the page table. Each page is classified on two axes.

              Shared          Private
           (mapped by       (mapped by
           multiple          only this
           processes)        process)
  ┌──────────────────┬──────────────────┐
  │  Shared_Clean    │  Private_Clean   │
  │  (can drop,      │  (can drop,      │
Clean  re-read file)     re-read file)   │
  │                  │                  │
  ├──────────────────┼──────────────────┤
  │  Shared_Dirty    │  Private_Dirty   │
  │  (must write     │  ★ MUST DUMP ★   │
Dirty  back to file)    (only in RAM)    │
  │                  │                  │
  └──────────────────┴──────────────────┘
RSS — Resident Set Size
Total pages in physical RAM for this VMA. Shared pages counted fully in each process → over-counts when many processes share libc, etc.
PSS — Proportional Set Size
Like RSS, but shared pages divided equally. If 10 processes share a 4KB page, each gets 0.4KB in PSS. Gives a fair per-process memory cost.
Size
Virtual size of the VMA (end - start). May be much larger than RSS — pages can be allocated but not yet faulted in, or swapped out.
