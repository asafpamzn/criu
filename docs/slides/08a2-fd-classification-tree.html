FD Dump: The Classification Tree

Type Detection & Dispatch

dump_one_file(pid, fd, lfd)
│
├─ S_ISSOCK? ──→ dump_socket()
│                ├─ AF_UNIX   → unix_sk_dump_ops
│                ├─ AF_INET   → inet_sk_dump_ops
│                ├─ AF_PACKET → packet_sk_dump_ops
│                └─ AF_NETLINK→ netlink_sk_dump_ops
│
├─ S_ISCHR? ───→ dump_chrdev()
│                ├─ MEM_MAJOR → regfile (/dev/null)
│                ├─ MISC+TUN  → tunfile_dump_ops
│                └─ is_tty?   → tty_dump_ops
│
├─ ANON_INODE_FS? → read link name
│                ├─ "eventfd"     → eventfd_dump_ops
│                ├─ "[eventpoll]" → eventpoll_dump_ops
│                ├─ "inotify"     → inotify_dump_ops
│                ├─ "signalfd"    → signalfd_dump_ops
│                ├─ "[timerfd]"   → timerfd_dump_ops
│                ├─ "pidfd"       → pidfd_dump_ops
│                └─ "bpf-map"     → bpfmap_dump_ops
│
├─ S_ISREG/DIR? → regfile_dump_ops
│                  or memfd_dump_ops
│                  or nsfile_dump_ops
│
└─ S_ISFIFO?
   ├─ PIPEFS → pipe_dump_ops
   └─ other  → fifo_dump_ops

How Classification Works

Step 1: fstat()
Get st_mode to distinguish sockets, regular files, FIFOs, char devices, block devices. This is the first branch.
Step 2: fstatfs()
Get filesystem magic number. Distinguishes PIPEFS_MAGIC, ANON_INODE_FS_MAGIC, SOCKFS_MAGIC, etc.
Step 3: readlink
For anon inodes, readlink(/proc/PID/fd/N) returns the type name: "eventfd", "[eventpoll]", "signalfd", etc.
Step 4: fdinfo
/proc/PID/fdinfo/N provides type-specific data: file position, flags, eventfd counter, epoll watched fds, timer settings, etc.
