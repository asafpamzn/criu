Solutions for Seamless TCP Migration

Three approaches to keep connections alive when the server moves.

1. Floating IP / VIP ✅ Best
Move the IP address to the new machine:

• AWS: Reassign ENI or secondary private IP
• On-prem: ARP gratuitous announcement (keepalived/VRRP)
• GCP: Alias IP range move

Same IP appears on new host → all existing connections continue via TCP_REPAIR.

Client impact: zero.
2. DNS Update
Update DNS record to point to new IP. Short TTL (e.g., 10s) means clients pick up change quickly.

Existing connections must reconnect. New connections go to the right place.

Good for stateless services. Problematic for long-lived connections like Valkey.
3. Load Balancer / Proxy
Client → NLB/HAProxy → backend.

Move backend routing rule. New connections go to new host. Existing connections through the proxy need the proxy to handle the switch.

NLB can do this with target group deregistration + re-registration.
CRIU's TCP_REPAIR preserves the TCP state byte-perfectly: sequence numbers, acknowledge numbers, congestion window, send/receive queues. Combined with a floating IP, the client literally cannot tell the server moved. The connection continues mid-byte.
