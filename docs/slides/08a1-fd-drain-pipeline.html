FD Dump: The 4-Step Drain Pipeline

1. Enumerate — collect_fds()
Read /proc/PID/fd/ directory to get all open FD numbers. Store them in a parasite_drain_fd array.
2. Drain — parasite_drain_fds_seized()
The parasite (running inside the target process) sends each FD to CRIU using SCM_RIGHTS over a Unix socket. This gives CRIU a local copy — CRIU can now fstat(), read(), and inspect each one.
3. Classify — dump_one_file()
For each drained FD, determine its type using:
• fstat() → S_ISSOCK, S_ISREG, S_ISFIFO, S_ISCHR
• fstatfs() → filesystem magic (PIPEFS, ANON_INODE_FS)
• /proc/PID/fdinfo/ → position, flags, type-specific data
4. Dispatch — fdtype_ops→dump()
Each FD type has its own dump handler (e.g., pipe_dump_ops, regfile_dump_ops). Serializes type-specific state into a protobuf image file.

Why SCM_RIGHTS?

The problem
CRIU (a separate process) can't directly access another process's file descriptors. /proc/PID/fd/N gives a symlink, but opening it creates a new file description — not the same one.
The solution
The parasite (running inside the target) uses sendmsg() with SCM_RIGHTS to pass the actual FD over a Unix socket. CRIU receives the exact same kernel file description — same offset, same flags, same locks.
Shared FD detection
Each FD gets a unique ID via fd_id_generate() using kcmp() to detect shared file descriptions. If two FDs in different processes point to the same kernel struct file, only dumped once.
