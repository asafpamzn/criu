Why Parent Holes Matter

Parent holes are the glue that makes incremental pre-dumps efficient.

Without parent holes
Every incremental pre-dump becomes a full dump. The restore side wouldn't know which pages to get from the parent vs. the current image. Parent holes make incremental pre-dump efficient.
Zero pages are different
Zero/unmapped pages are NOT in the page-pipe at all. They don't need parent images — the kernel naturally provides zeros via fresh anonymous pages. Don't confuse them with parent holes!
First pre-dump: no holes
has_parent=false, so page_in_parent() always returns false. All present pages classified as dirty → all get dumped. Parent holes only appear from the 2nd pre-dump onward.
Restore resolution
On restore, CRIU walks layers newest-first:

• Dirty page found → use it
• Parent hole → look in parent layer
• Zero → leave unmapped

Each page resolved exactly once.
Analogy: Think of it like Docker image layers. Each layer only stores what changed. A "parent hole" is like a transparent pixel — it means "inherit from the layer below". The bottom layer has no holes because there's nothing below it.
