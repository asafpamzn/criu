Freeze vs. Convergence: What Changes?

Captured Once at Initial Freeze

These are point-in-time snapshots — the process is ptrace-seized, so they can't change.

✓ Thread registers, TLS, rseq
Captured via ptrace at dump. Threads are frozen — registers don't change.
✓ File descriptors
Drained via parasite SCM_RIGHTS. Process frozen → can't open/close FDs.
✓ Signal handlers + pending signals
sigaction table + PTRACE_PEEKSIGINFO queues. Stable while frozen.
✓ Timers (itimer + POSIX)
Read via parasite. Timer values frozen at dump time.
✓ Credentials, rlimits, cgroups, namespaces
All kernel metadata. Can't change while ptrace-seized.
✓ Filesystem context (cwd, root, umask)
Process identity. Stable.
✓ VMA layout (at dump time)
Memory map from /proc/PID/smaps. Captured once, used as baseline.

Must Be Re-captured at Convergence

After early resume, the process is running and mutating these resources.

✗ Dirty memory pages
The core problem. Process writes to pages tracked by WP_ASYNC. PAGEMAP_SCAN(PAGE_IS_WRITTEN) finds them, atomically re-arms WP. Multiple iterative rounds until convergence (dirty count → 0).
✗ New VMAs (mmap extents)
jemalloc / allocators create new mmap() regions during migration. Not in the dump-time VMA list. Detected by comparing live /proc/PID/maps with dump-time VMAs. Sent as PS_IOV_VMA_DIFF + page data. Replica injects mmap(MAP_FIXED) via ptrace.
⚠ Temporal consistency
Reading dirty pages from a live process creates cross-page inconsistency (page A from time T₁, page B from T₂ → corrupted allocator metadata). Solution: fork-snapshot. CRIU injects clone(SIGCHLD) via ptrace → reads ALL dirty pages from the COW fork → kills fork.
⚠ libc rw- exclusion
glibc main_arena rw- pages are excluded from convergence. Bulk transfer already sent the clean dump-time snapshot. Overwriting with live state would corrupt fastbins/bins metadata.
