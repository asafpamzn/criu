What Can Change After Early Resume?

In COW WP_ASYNC mode, the source process is alive and running after the ~51ms dump freeze. Everything the process can do at runtime can happen during the bulk transfer window (~58s for 100GB).

⚠ Can Change — NOT Re-captured

These are captured once at dump freeze. If the source mutates them afterward, the replica gets stale state. Known limitation of current COW implementation.

⚠ Threads
Source can pthread_create() / pthread_exit() new threads. Registers, TLS, rseq captured once via ptrace — new threads won't exist in the image.
⚠ File Descriptors
Source can open(), close(), dup2(), accept(). FD table drained once via parasite — new FDs not captured. Closed FDs still in image.
⚠ Signal Handlers
Source can sigaction() to change handlers. Pending signals can arrive. PTRACE_PEEKSIGINFO only done at dump time.
⚠ Timers
setitimer(), timer_create() / timer_settime() can change. Values captured once via parasite at dump.
⚠ Credentials, rlimits, cgroups
Theoretically mutable (e.g. setrlimit(), cgroup migration). Not re-read at convergence.
⚠ Filesystem context
chdir(), chroot(), umask() — all mutable at runtime. Captured once.
Why it works for Valkey: Valkey's event loop doesn't create/destroy threads, change signal handlers, open new FD types, or chdir() during normal request processing. It's a well-behaved single-event-loop server. For a general-purpose solution, all of these would need re-dumping at convergence (like pre-dump → dump).

✓ Re-captured at Convergence

These are tracked during runtime and re-sent before cutover.

✓ Dirty memory pages
The core of COW convergence. WP_ASYNC + PAGEMAP_SCAN(PAGE_IS_WRITTEN) finds all pages written since bulk transfer. Atomically re-arms WP. Multiple rounds until dirty count → 0.
✓ New VMAs (mmap extents)
Allocators (jemalloc) create new anonymous mmap() regions. Detected by comparing live /proc/PID/maps with dump-time VMA list. Sent as PS_IOV_VMA_DIFF + page data. Replica injects mmap(MAP_FIXED) via ptrace.
✓ Temporal consistency (fork snapshot)
Reading dirty pages from a live process creates cross-page inconsistency. Solution: inject clone(SIGCHLD) via ptrace → COW fork snapshot → read ALL dirty pages from fork → kill fork. All pages from one point in time.
⚠ libc rw- exclusion
glibc main_arena pages excluded from convergence. Bulk transfer sent clean dump-time snapshot. Overwriting with live state would corrupt allocator metadata (fastbins/bins).
The general pattern: Just like pre_dump only captures memory and the full dump captures everything, COW convergence currently only handles memory. A full general-purpose COW migration would need to re-dump threads, FDs, signals, etc. at convergence time — essentially a "second dump" of the non-memory state.
