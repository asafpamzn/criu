maps vs smaps — What's the Difference?

Both live in /proc/PID/ and describe virtual memory areas, but smaps is far more expensive.

/proc/PID/maps — Lightweight

7f8a00000000-7f8a04000000 rw-p 00000000 00:00 0
7f8a04000000-7f8a08000000 ---p 00000000 00:00 0
7f8a1c000000-7f8a1c021000 rw-p 00000000 00:00 0
7f8a1e800000-7f8a1e828000 r--p 00000000 fe:01 1234 /usr/lib/libc.so.6

One line per VMA. Each line contains:

  • Address range: start-end
  • Permissions: r/w/x + p(rivate)/s(hared)
  • Page offset, device, inode
  • File path or name ([heap], [stack], [vdso])
⚡ Fast: reads VMA metadata from kernel's vm_area_struct linked list. No page table walk. O(number of VMAs).

/proc/PID/smaps — Heavyweight

7f8a00000000-7f8a04000000 rw-p 00000000 00:00 0
Size:             65536 kB
Rss:              32768 kB
Pss:              32768 kB
Shared_Clean:         0 kB
Shared_Dirty:         0 kB
Private_Clean:    16384 kB
Private_Dirty:    16384 kB
Referenced:       32768 kB
Anonymous:        32768 kB
VmFlags: rd wr mr mw me ac

Same VMA header + multi-line per-VMA stats:

  • RSS/PSS/Shared/Private — memory accounting
  • Referenced, Anonymous, LazyFree — page states
  • VmFlags — kernel VM flags as 2-letter codes
🐌 Slow: kernel walks the entire page table for every VMA, examining each PTE to compute dirty/clean/shared/private counts. For 100GB Valkey = ~26 million PTEs = seconds of CPU time.
