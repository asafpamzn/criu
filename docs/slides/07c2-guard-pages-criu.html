MADV_GUARD — How CRIU Handles Them

// collect_mappings() in cr-dump.c
// Collected AFTER parsing maps/smaps:
if (dump_file) {  // only during full dump
    ret = collect_madv_guards(pid, vma_area_list);
}
Collection
collect_madv_guards() uses a kernel interface to discover guard pages that are invisible in maps/smaps. Each guard page is stored as a VMA entry with only the VMA_AREA_GUARD flag set — no permissions, no file backing, no page content.
Restore
On restore, CRIU calls madvise(MADV_GUARD_INSTALL) to recreate each guard page at its original address. Without this, the restored process would lose stack overflow protection.
Skipped in Pre-dump
Guard pages have no memory content to transfer — they're just markers. So pre_dump_one_task skips them entirely (the dump_file parameter is NULL during pre-dump).
🔑 Linux 6.x feature. Older kernels use the VMA-based MAP_GROWSDOWN guard gap instead, which IS visible in maps/smaps.
