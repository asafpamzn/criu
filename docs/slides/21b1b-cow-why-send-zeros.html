COW: Why Send Zeros Instead of Skipping?

Skipping unmapped pages would cause deadlocks on the replica.

Why not just skip?

Deadlock scenario
If COW skips an unmapped page, the replica's userfaultfd will fault on that address later when the process accesses it. The page server can't service the fault — the source never had that page mapped.

→ Replica process hangs forever waiting for a page that will never arrive.
No layered images in COW mode
COW sends ALL pages in one pass. No PP_HOLE_PARENT. No parent layers. The replica gets a complete memory image directly — every address in the VMA range must be accounted for.

Why zeros are cheap

LZ4 compression to the rescue
A 4KB zero page compresses to ~20 bytes on the wire. For a 100GB process with 50% zero pages, the extra network cost is:

12.8M zero pages × 20 bytes = ~256 MB
vs 50GB uncompressed. That's 0.5% overhead.
The real cost: RSS bloat on replica
The problem isn't network — it's that process_vm_writev() on the replica materializes zero pages into physical RAM. This causes RSS bloat. See next slide for the fix.
Summary: Sending zeros = safe + cheap on network. Skipping = deadlock. The tradeoff is replica RSS bloat (fixable separately).
