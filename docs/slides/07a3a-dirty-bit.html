Dirty Pages: The Hardware Dirty Bit

What Is the Dirty Bit?

Every page of memory has a Page Table Entry (PTE) in the CPU's page table. One bit in the PTE is the dirty bit:

Clean Page (dirty=0)
Content matches its source. For file-backed pages: matches the file on disk. For anonymous pages after fork: matches the parent's copy. The kernel can drop clean file pages — just re-read from disk later.
Dirty Page (dirty=1)
The process has written to this page. In-memory content differs from the backing source. For anonymous pages (heap/stack): data exists only in RAM — losing it means data loss.

PTE Layout (x86_64)

Page Table Entry (PTE):
┌─────────────────────────────────┐
│ Physical Address │ Flags        │
│ (bits 12-51)     │ D=dirty      │
│                  │ A=accessed   │
│                  │ R/W=writable │
│                  │ P=present    │
└─────────────────────────────────┘
CPU sets the D bit automatically
on first write — no software needed.

What CRIU must dump

Classification for dump
Clean file-backed → skip (re-read from file on restore)
Dirty file-backed → MUST dump (differs from file)
Anonymous pages → MUST dump (no backing file)

A 100GB Valkey = mostly anonymous heap → nearly all pages must be dumped.
