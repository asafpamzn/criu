Step 1 Deep Dive: Personality — Execution Domain

static int get_task_personality(pid_t pid, u32 *personality) {
    fd = open_proc(pid, "personality");
    ret = read(fd, loc_buf, sizeof(loc_buf) - 1);
    *personality = atoi(loc_buf);
}

What is personality?

A 32-bit value read from /proc/PID/personality that controls how the kernel behaves for this process. It's a bitmask combining a base personality (low byte) with flags (high bytes).

Set via personality() syscall or inherited from parent. Typically set by the dynamic loader or by exec of a 32-bit binary on a 64-bit kernel.

Common Base Personalities

PER_LINUX (0x0000)
Default. Standard Linux behavior. 64-bit process on 64-bit kernel, or 32-bit on 32-bit kernel.
PER_LINUX32 (0x0008)
32-bit compatibility mode on a 64-bit kernel. uname -m reports i686 instead of x86_64. Syscall numbers follow 32-bit ABI.
PER_LINUX_32BIT (0x0000 | ADDR_LIMIT_32BIT)
Limits virtual address space to 32-bit range. Used for some legacy binaries that assume 32-bit pointers.

Personality Flags (OR'd with base)

ADDR_NO_RANDOMIZE (0x0040000)
Disables ASLR (Address Space Layout Randomization). Stack, mmap, heap, and vDSO addresses become deterministic. Used for debugging or by processes that need reproducible memory layouts.
ADDR_LIMIT_32BIT (0x0800000)
Restricts mmap to the low 32-bit address range. Ensures all pointers fit in 32 bits.
SHORT_INODE (0x1000000)
Report 16-bit inode numbers. Compatibility for ancient filesystems.
READ_IMPLIES_EXEC (0x0400000)
All readable pages are also executable. Legacy behavior for old binaries without proper ELF flags. Security concern — CRIU must preserve it exactly.
🔑 Why CRIU needs this: A 32-bit Valkey on a 64-bit host uses PER_LINUX32. Restoring without the correct personality would break syscall numbering, uname output, and address space layout. A process with ADDR_NO_RANDOMIZE restored with ASLR enabled would get different memory addresses — potentially crashing.
