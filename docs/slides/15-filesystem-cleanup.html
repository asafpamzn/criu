Step 10: Filesystem, MM & Cleanup

The final steps happen after the parasite is removed.

Filesystem Context

ret = dump_task_fs(pid, &misc, cr_imgset);
  • cwd — current working directory (/proc/PID/cwd)
  • root — filesystem root (/proc/PID/root)
  • umask — file creation mask (from parasite misc)

Memory Map Metadata

ret = dump_task_mm(pid, &pps_buf,
                   &misc, &vmas, cr_imgset);
  • VMA descriptors (start, end, flags, file ID)
  • Code/data/stack/brk boundaries
  • auxv — auxiliary vector (/proc/PID/auxv)
  • exe link — path to the executable
  • AIO rings metadata

The Cure — Removing the Parasite

// Three variants depending on mode:
if (opts.clone_dump && opts.lazy_pages)
    ret = compel_cure_local(parasite_ctl);
else if (opts.lazy_pages)
    ret = compel_cure_remote(parasite_ctl);
else
    ret = compel_cure(parasite_ctl);
compel_cure()
Full cleanup: restore registers, munmap parasite blob remotely, detach ptrace
compel_cure_remote()
Restore registers + munmap, but keep local mappings (for lazy pages transfer)
compel_cure_local()
Only clean up CRIU-side state. Leave parasite blob in target (CLONE mode — it's harmless, covered by WP tracking)
