COW Mode: Handling Unmapped Pages

COW mode skips pagemap — unmapped pages are discovered at read time and sent as zeros.

Standard CRIU: knows before reading

// should_dump_page() checks pagemap:
if (!(pme & (PME_PRESENT | PME_SWAP)))
    skip;  // not in RAM or swap
if (__page_is_zero(pme))
    skip;  // kernel zero page

COW Mode: discovers at read time

// send_lazy_vma_page() in page-xfer.c:
ret = process_vm_readv(source_pid,
    &local_iov, 1, &remote_iov, 1, 0);

if (ret != PAGE_SIZE) {
    if (ret < 0 && saved_errno == EFAULT) {
        memset(buffer, 0, PAGE_SIZE);
        // Falls through → sends the zero page!
    } else {
        return -1;
    }
}
// BOTH normal and EFAULT pages reach here:
data = cow_pg ? cow_pg->data : buffer;
send_page_compressed(sk, data, dst_id, vaddr);

Key insight: zero pages ARE sent

What happens on EFAULT
Buffer is zero-filled and sent to the replica. The replica writes it via process_vm_writev. This materializes a zero page consuming physical memory on the replica.
Why this is acceptable
1. Source unmapped it after snapshot — replica represents dump-time state
2. jemalloc will reclaim it on next cycle
3. Rare — only on VMA trim during transfer
4. LZ4 zero page ≈ 20 bytes on wire
The alternative is worse
Skipping → replica userfaultfd faults on that address, page server can't service (source unmapped). → Deadlock. Zeros = safe path.
No layered images
COW sends ALL pages in one pass. No PP_HOLE_PARENT. Replica gets a complete memory image directly.
Works for Valkey
Dense jemalloc allocation → very few unmapped holes in 200GB. Zero-fill overhead is negligible.
🔮 Future improvement
Send a VMA shrink diff instead of zeros — tell replica to munmap() (like PS_IOV_VMA_DIFF for new VMAs). Avoids materializing dead pages. Low priority — few hundred pages out of 52M.
