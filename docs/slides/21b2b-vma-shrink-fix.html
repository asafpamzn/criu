🔮 Future Fix: VMA Shrink Diff

Tell the replica to munmap() instead of sending zero pages.

Current: Send Zeros

Source: page unmapped (EFAULT)
  → memset(buf, 0, PAGE_SIZE)
  → send_page_compressed(zero page)

Replica: process_vm_writev(zeros)
  → physical page allocated ❌
  → RSS bloat
Works but wasteful
Every unmapped page becomes a real physical page on the replica. For sparse allocators, this can add up to significant RSS overhead.

Better: Send VMA Shrink

Source: detects VMA shrank
  → send PS_IOV_VMA_SHRINK to replica

Replica: munmap(old_end, shrink_size)
  → no physical pages wasted ✅
  → RSS matches source exactly
Similar to existing VMA diff
We already have PS_IOV_VMA_DIFF for new VMAs that appear during transfer. A shrink diff is the reverse — tell the replica to munmap() ranges that disappeared. Same protocol, opposite direction.
Priority: LOW
For dense Valkey heaps, the bloat is typically a few hundred pages out of 52M (<0.001%). Only matters for sparse allocators with many unmapped holes. Deferred until real-world need arises.
