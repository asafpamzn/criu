AWS: Moving IPs Between EC2 Instances

Two approaches: move a secondary private IP, or move an entire ENI.

Option A: Move Secondary Private IP

Fastest. Same subnet required. ~1-2 seconds.

# Setup: assign a secondary IP to source instance
aws ec2 assign-private-ip-addresses \
  --network-interface-id eni-source-abc123 \
  --private-ip-addresses 10.0.1.100

# Valkey listens on 10.0.1.100:6379
# Clients connect to 10.0.1.100:6379

# === MIGRATION CUTOVER ===

# Step 1: Unassign from source
aws ec2 unassign-private-ip-addresses \
  --network-interface-id eni-source-abc123 \
  --private-ip-addresses 10.0.1.100

# Step 2: Assign to replica
aws ec2 assign-private-ip-addresses \
  --network-interface-id eni-replica-def456 \
  --private-ip-addresses 10.0.1.100

# Step 3: Configure IP on replica OS
ssh replica "sudo ip addr add 10.0.1.100/24 \
  dev eth0"

# Clients' TCP connections resume on replica!
Requirements
• Both instances in same subnet (same AZ)
• Secondary IP (not the primary IP of the instance)
• Security groups allow traffic on port 6379
• ~1-2s for AWS API + ARP propagation

Option B: Move Entire ENI

More powerful. Moves all IPs, security groups, MAC address.

# Setup: create a dedicated ENI for Valkey
aws ec2 create-network-interface \
  --subnet-id subnet-abc123 \
  --private-ip-address 10.0.1.100 \
  --groups sg-valkey-abc123

# Attach to source instance (as eth1)
aws ec2 attach-network-interface \
  --network-interface-id eni-valkey-xyz789 \
  --instance-id i-source-111 \
  --device-index 1

# === MIGRATION CUTOVER ===

# Step 1: Detach from source
ATTACH_ID=$(aws ec2 describe-network-interfaces \
  --network-interface-ids eni-valkey-xyz789 \
  --query 'NetworkInterfaces[0].Attachment.AttachmentId' \
  --output text)

aws ec2 detach-network-interface \
  --attachment-id $ATTACH_ID --force

# Step 2: Wait for detach
aws ec2 wait network-interface-available \
  --network-interface-ids eni-valkey-xyz789

# Step 3: Attach to replica
aws ec2 attach-network-interface \
  --network-interface-id eni-valkey-xyz789 \
  --instance-id i-replica-222 \
  --device-index 1

# Step 4: Configure on replica OS
ssh replica "sudo dhclient eth1"
Requirements
• Both instances in same AZ (ENIs can't cross AZs)
• ENI must be a secondary interface (not primary eth0)
• Moves: all private IPs, security groups, MAC, Elastic IPs
• ~5-10s for detach + attach cycle
Migration Timeline
CRIU dump (51ms) → page transfer (58s) → cutover: {
  1. CRIU restore on replica (1ms)
  2. Move IP (1-2s) ← AWS API call
  3. SIGCONT restored process
} → client traffic resumes
⚠️ Cross-AZ limitation
Neither option works across AZs. For cross-AZ migration, you need:
• Route 53 DNS failover (client reconnects), or
• Global Accelerator with endpoint switching, or
• NLB with cross-AZ target group update
