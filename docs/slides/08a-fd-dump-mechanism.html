How CRIU Dumps File Descriptors

The 4-Step FD Drain Pipeline

1. Enumerate — collect_fds()
Read /proc/PID/fd/ directory to get all open FD numbers. Store them in a parasite_drain_fd array.
2. Drain — parasite_drain_fds_seized()
The parasite (running inside the target process) sends each FD to CRIU using SCM_RIGHTS over a Unix socket. This gives CRIU a local copy of the FD — CRIU can now fstat(), read(), and inspect each one.
3. Classify — dump_one_file()
For each drained FD, determine its type using:
• fstat() → S_ISSOCK, S_ISREG, S_ISFIFO, S_ISCHR
• fstatfs() → filesystem magic (PIPEFS, ANON_INODE_FS)
• /proc/PID/fdinfo/ → position, flags, type-specific data
• readlink(/proc/PID/fd/N) → link name for anon types
4. Dispatch — fdtype_ops→dump()
Each FD type has its own dump handler (e.g., pipe_dump_ops, regfile_dump_ops, eventfd_dump_ops). The handler serializes type-specific state into a protobuf image file.

The Classification Tree

dump_one_file(pid, fd, lfd)
│
├─ S_ISSOCK? ──→ dump_socket()
│                ├─ AF_UNIX  → unix_sk_dump_ops
│                ├─ AF_INET  → inet_sk_dump_ops
│                ├─ AF_PACKET→ packet_sk_dump_ops
│                └─ AF_NETLINK→ netlink_sk_dump_ops
│
├─ S_ISCHR? ───→ dump_chrdev()
│                ├─ MEM_MAJOR → regfile (e.g. /dev/null)
│                ├─ MISC+TUN  → tunfile_dump_ops
│                └─ is_tty?   → tty_dump_ops
│
├─ ANON_INODE_FS? → read link name
│                ├─ "eventfd"  → eventfd_dump_ops
│                ├─ "[eventpoll]" → eventpoll_dump_ops
│                ├─ "inotify"  → inotify_dump_ops
│                ├─ "signalfd" → signalfd_dump_ops
│                ├─ "[timerfd]"→ timerfd_dump_ops
│                ├─ "pidfd"    → pidfd_dump_ops
│                └─ "bpf-map"  → bpfmap_dump_ops
│
├─ S_ISREG/DIR? → regfile_dump_ops
│                  or memfd_dump_ops
│                  or nsfile_dump_ops
│
└─ S_ISFIFO?
   ├─ PIPEFS → pipe_dump_ops
   └─ other  → fifo_dump_ops
Each FD is assigned a unique ID via fd_id_generate() (using kcmp() to detect shared file descriptions). If two FDs in different processes point to the same kernel struct file, they get the same ID — only dumped once.
