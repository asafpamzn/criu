maps vs smaps: The Performance Gap

// collect_mappings() in cr-dump.c
use_maps = opts.clone_dump && opts.lazy_pages;
ret = use_maps ? parse_maps(pid, vma_area_list, dump_file)
               : parse_smaps(pid, vma_area_list, dump_file);

What smaps Provides (expensive)

VmFlags line
2-letter codes for kernel VM flags:
gd=MAP_GROWSDOWN, lo=MAP_LOCKED,
nr=MAP_NORESERVE, ht=MAP_HUGETLB,
io/pf=VM_IO/VM_PFNMAP (unsupported),
sr, rr, dc, mg, hg, nh, wf = madvise flags
Memory accounting stats
RSS, PSS, Shared/Private Clean/Dirty — the kernel must walk all PTEs to compute these. For 200GB = 52M pages → takes 2-5 seconds.

What maps Provides (cheap)

Just the VMA boundaries
Address range, permissions, offset, device, inode, filename.
No page table walk — just iterates kernel vm_area_struct linked list.
Cost: <1 millisecond regardless of memory size.
