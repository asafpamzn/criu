Socket FDs: The Most Complex Case

TCP Sockets — sk-tcp.c + soccr library
The hardest FD type to checkpoint. Must preserve a live connection.

Dump:
1. Put socket into TCP_REPAIR mode (kernel API)
2. Read full TCP state: seq/ack numbers, window, timestamps, congestion algorithm + state, MSS, options
3. Read queued data: send queue, receive queue, out-of-order queue via TCP_REPAIR_QUEUE
4. Save source/dest IP:port, socket options

Restore:
1. Create socket in TCP_REPAIR mode
2. Bind + connect (succeeds immediately in repair mode)
3. Inject all queued data back
4. Restore seq numbers, window, timestamps
5. Exit repair mode — connection appears uninterrupted

Network lock: CRIU blocks network traffic with iptables/nftables during dump to prevent new data arriving.
UDP Sockets — sk-inet.c
Saved: bind address:port, connect address (if connected), socket options (SO_REUSEADDR, SO_BROADCAST, etc.), pending data in receive queue

Simpler than TCP: no connection state, no sequence numbers. Just re-create the socket and re-bind. Data in transit is lost (UDP has no delivery guarantees anyway).
Unix Sockets — sk-unix.c
Saved: socket type (stream/dgram/seqpacket), bound path or abstract name, peer (who's connected), socket state, queued data (in both directions), socket options, file owner

Challenges:
• Connected pairs must be restored together (like pipe ends)
• External connections (to processes outside the dump tree) are handled via --external unix[inode] or the fd inherit mechanism
• Passed FDs in the queue (via SCM_RIGHTS) must also be dumped

Source: sk-unix.c, sk-queue.c
Netlink Sockets — sk-netlink.c
Saved: protocol (NETLINK_ROUTE, NETLINK_GENERIC, etc.), port ID, multicast groups, socket options

Used by processes to talk to the kernel (routing tables, network config). On restore, re-create with same protocol and re-bind to same port ID.
Packet Sockets — sk-packet.c
Saved: protocol, bound interface, fanout config, socket options, ring buffer config (TPACKET versions)

Raw network access (e.g., tcpdump). On restore, re-create and re-bind to interface. Relatively rare in typical workloads.
Restore FD distribution: One "master" process opens the FD, then distributes copies to all other processes that need it via SCM_RIGHTS over a CRIU transport socket (send_fd_to_peer() / recv_fd_from_peer()).
