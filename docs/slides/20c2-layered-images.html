The Layered Image Model

Incremental pre-dumps build a stack of image layers. Parent holes are the glue.

How Layers Stack

Pre-dump 1 (parent) — no baseline
has_parent=false → ALL present pages dumped
Page A Page B zero Page D
↓ clear_refs → process runs → some pages modified
Pre-dump 2 (incremental) — has parent
Only dirty pages + parent holes
hole→A Page B' zero hole→D
↓ clear_refs → process runs → fewer pages modified
Final dump — smallest delta
Mostly parent holes, few dirty pages
hole→A hole→B' zero Page D'

Why parent holes matter

Without parent holes
Every incremental pre-dump becomes a full dump. The restore side wouldn't know which pages to get from parent vs current image. Parent holes make incremental pre-dump efficient.
Zero pages are different
Zero/unmapped pages are NOT in the page-pipe at all. They don't need parent images — the kernel naturally provides zeros. Don't confuse them with parent holes!
First pre-dump: no holes
has_parent=false, so page_in_parent() always returns false. All present pages classified as dirty → all get dumped. Parent holes only appear from the 2nd pre-dump.
Restore resolution
On restore, CRIU walks layers newest-first. Dirty page found → use it. Parent hole → look in parent layer. Zero → leave unmapped. Each page resolved exactly once.
