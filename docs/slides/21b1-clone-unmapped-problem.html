CLONE Mode: The Unmapped Page Problem

CLONE mode skips pagemap — so how does it handle pages that aren't in memory?

Standard CRIU: knows before reading

// should_dump_page() checks pagemap:
if (!(pme & (PME_PRESENT | PME_SWAP)))
    skip;  // not in RAM or swap
if (__page_is_zero(pme))
    skip;  // kernel zero page
// → never tries to read unmapped pages
Pagemap tells you what's there
Each 8-byte entry says: present? in swap? soft-dirty? zero page? Standard CRIU skips unmapped pages before ever touching them.

CLONE Mode: discovers at read time

// send_lazy_vma_page() in page-xfer.c:
ret = process_vm_readv(source_pid,
    &local_iov, 1, &remote_iov, 1, 0);

if (ret != PAGE_SIZE) {
    if (ret < 0 && errno == EFAULT) {
        // Page not mapped! Can't read it.
        memset(buffer, 0, PAGE_SIZE);
        // Fall through → send zeros
    }
}
// BOTH normal and EFAULT pages sent:
send_page_compressed(sk, data, dst_id, vaddr);
EFAULT = page not in memory
process_vm_readv() returns EFAULT for addresses that have no physical page. CLONE mode zero-fills the buffer and sends it as a zero page.
Why not just skip? If CLONE skips the unmapped page, the replica's userfaultfd will fault on that address later. The page server can't service the fault (source unmapped the page). → Deadlock. Sending zeros is the safe path — the replica gets a complete memory image with no holes to fill later.
No layered images
CLONE sends ALL pages in one pass. No PP_HOLE_PARENT. Replica gets a complete memory image directly.
LZ4 compression helps
A zero page compresses to ~20 bytes on the wire. Network cost is negligible.
